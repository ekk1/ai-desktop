# 本地 AI 工作台总体设计

**日期：** 2026-08-30

**状态：** 已批准；阶段 1–6 已交付，阶段 7 待实施

**运行环境：** Linux 单用户服务，通过 SSH 隧道访问

## 1. 产品目标

构建一个本地 AI 工作台，用于组装完整的 LLM 请求、管理本地 AI Server 进程、批量生成图片和视频，以及在这些工作流之间复用媒体资产。

本产品是“完整请求工作台”，不是聊天客户端。会话只负责组织一棵可分支的 Panel 树以及执行结果；Panel 不具有 `user`、`assistant` 或 `system` 语义。每次执行都会重新组装并发送一个完整请求。

## 2. 固定约束

- 工作台是单个 Go 二进制，只使用 Go 标准库；可选远端 Worker 是同仓库构建的第二个独立命令，同样只使用标准库。
- Server 只在 Linux 上运行，并且只监听 `127.0.0.1`。
- 远程浏览器通过 SSH 隧道访问；不实现登录、鉴权、CSRF 或多用户权限。
- 浏览器端只使用仓库自有的 HTML、CSS 和 JavaScript；不使用前端框架、包管理器、构建工具、CDN、图标库或其他第三方运行时依赖。
- 前端静态资源使用 `go:embed` 嵌入 Go 二进制。
- 持久化使用带版本号的 JSON/JSONL 文件，不引入数据库驱动。
- AI Server、`bash`、用户配置的生成 CLI 和可选的 `ffmpeg` 是外部程序，不是 Go 依赖。
- Provider API Key 直接保存在主配置文件中；程序创建配置文件时使用 `0600` 权限。

## 3. 总体架构

工作台采用模块化单体。一个进程负责 HTTP Server、嵌入式前端、文件存储、Provider 请求、生成队列、资产索引以及本机子进程管理。可选的远端 `ai-worker` 只负责一个远端 Linux 进程组，不持有工作台数据。

内部按职责拆分：

- `app`：启动、关闭、路由装配、配置和依赖组装。
- `store`：版本化文件、原子替换、备份恢复和数据迁移。
- `backend`：可配置的 Linux 子进程及临时日志。
- `worker`：远端进程控制协议与客户端；独立 `cmd/ai-worker` 提供最小服务端。
- `session`：文件夹、会话、Panel 树、修订记录和执行快照。
- `provider`：LLM、Exa HTTP 客户端和 Provider 配置。
- `asset`：媒体导入、内容文件、元数据、引用和精选状态。
- `knowledge`：备忘录文件夹、条目、标签和资产引用。
- `imagegen`：生图批次、图像参数、请求和结果。
- `videogen`：视频批次、视频参数、HTTP/CLI 执行、工作区和尾帧提取。
- `web`：HTTP Handler、JSON 校验、静态资源、SSE 和面向前端的数据结构。

模块之间只传递稳定 ID 和明确的数据结构，不直接编辑其他模块的 JSON 文件。例如，生图成功后调用 `asset` 导入文件，并保存返回的资产 ID。

## 4. 数据目录与持久化

程序支持 `--data-dir` 指定唯一数据根目录。未指定时，从 Linux 用户数据目录解析 `ai-workbench` 子目录。最终路径必须是绝对路径，不受程序启动目录变化影响。

```text
data/
├── config.json
├── instance.lock
├── backends/
│   ├── profiles.json
│   └── crash-logs/
├── sessions/
│   └── <session-id>/
│       ├── workspace.json
│       └── runs/
│           └── <run-id>.json
├── knowledge/
├── images/
│   └── batches/
├── videos/
│   └── batches/
├── assets/
│   ├── index.json
│   └── files/
├── video-workspace/
└── tmp/
```

存储规则：

- 每份结构化文档都包含 `schema_version`，由 Go 迁移函数逐版本升级。
- 写入流程为：在目标目录写临时文件、`fsync`、原子重命名。
- 重要索引保留一份最近的 `.bak`，只用于损坏恢复。
- 启动时清理未完成的临时上传；上次仍在运行的生成任务标记为“已中断”，不自动重发。
- 同一数据目录只允许一个工作台实例持有锁，避免并发改写。

## 5. 后端进程管理

### 5.1 后端配置

每个后端配置包含：

- ID、名称、说明和标签。
- 原始 Shell 启动命令。
- 绝对路径或相对数据目录的工作目录。
- 环境变量表。
- 命名模板变量及默认值。
- 可选就绪规则：HTTP 健康检查、日志正则或固定等待时间。
- 停止宽限时间和内存日志容量。

运行时可以新增、复制、编辑和删除配置。修改正在运行的配置只影响下一次启动；当前实例保留启动时的不可变配置快照，界面提示“配置已变更”。

命令通过 `/bin/bash -lc` 执行，并创建独立的 Linux 进程组。模板变量同时提供 Shell 安全引用形式和原始替换形式。原始替换保留给受信任的本地用户，用于管道、重定向和复合命令。

### 5.2 运行规则

- 同一个后端配置最多有一个活动实例。
- 不同后端配置可以同时运行。
- 不检测配置之间的 GPU、显存、模型或端口冲突。
- 停止时先向整个进程组发送 `SIGTERM`，等待配置的宽限时间，之后按需发送 `SIGKILL`。
- 运行状态为 `starting`、`running`、`stopping`、`stopped` 和 `failed`。
- 工作台正常退出时，停止它启动的所有子进程。
- 工作台崩溃后，旧运行记录标记为状态未知；不接管或终止旧 PID，避免误伤后来复用该 PID 的无关进程。

### 5.3 日志

stdout 和 stderr 写入同一个有容量上限的内存环形缓冲区和浏览器事件流。显示与保存的内容保持 Server 原始文本，不添加时间戳、来源标签或 JSONL 包装。

正常运行期间不持久化日志。用户点击“保存日志”时才写入普通文本文件；子进程异常退出时，自动把当前缓冲区写为 crash log。界面仅提供实时查看、暂停/恢复自动滚动、文本搜索、清空视图和保存。

Server 到浏览器使用 SSE。SSE 载荷可以用 JSON 字符串运输文本块，但渲染和保存时只输出原始内容。

### 5.4 远端执行

后端 Profile 可以选择本机执行或远端 Worker 执行。Worker 只绑定云端回环地址，任一时刻只管理一个进程组；工作台通过一条 SSH 隧道控制 Worker，通过另一条隧道直接访问模型 Server。Worker 不保存 Profile、Prompt、Asset、结果或日志文件，也不提供文件传输和生成 API。

完整协议、断线语义和界面集成见[远端进程 Worker 设计](2026-08-31-remote-worker-design.md)。

## 6. LLM 请求工作区

### 6.1 组织与分支

层级为“文件夹 → 会话 → Panel 树”。会话是请求工作区的组织容器，不代表对话协议；标题和所属文件夹由用户手工修改，不调用 AI 自动生成。

每个 Panel 包含：

- ID、父 ID、子节点顺序、标题和内容。
- 文本、JSON 或资产引用等内容表现形式；它只决定编辑和预览方式，不代表 LLM 角色。
- 是否加入请求，以及用户控制的请求内顺序。
- 折叠状态。
- 修订记录和时间信息。
- 可选执行元数据及不可变运行快照链接。

主界面只渲染当前选中的“根节点到当前节点”路径。只有存在兄弟节点时才显示紧凑的分支选择器。用户可从任意节点执行并创建子分支，不覆盖原分支；同一完整请求发送给多个快捷 Provider 时，结果成为兄弟 Panel。

### 6.2 完整请求组装

执行时收集当前分支上已启用的 Panel，再加入用户明确选择的模板、知识条目和 active 资产。组装器生成不可变快照，记录当时的完整内容、Provider 配置、参数和资产版本。

返回值创建为新的普通 Panel。它没有 assistant 角色，可以继续编辑、排除、调整顺序或用于下一次完整请求。

### 6.3 LLM Provider

默认本地适配器使用 llama.cpp 原生 `POST /completion`，因为它可以直接接受一份无聊天角色的完整 prompt，并支持同步和流式返回。默认就绪检测使用 `GET /health`。

其他预设可以使用 OpenAI 兼容的 completions、chat completions 或 responses 端点。遇到基于角色的线上协议时，适配器只在网络层把组装结果包装成单个输入，不把角色带进 Panel 模型。原始 HTTP Provider 可编辑 URL、方法、请求头、JSON Body 模板、流模式和响应提取路径。

Provider 配置直接包含 API Key。快捷路径把 Provider、模型和默认采样参数绑定成一个短名称，并作为工作区的发送按钮显示。

模板使用受控变量，例如 `${CONTENT_JSON}`、`${MODEL_JSON}` 和 `${ASSET_DATA_URLS_JSON}`。以 `_JSON` 结尾的变量始终经过 JSON 编码，防止产生无效请求体。Provider 配置不能执行 JavaScript 或 Go 模板代码。

官方参考：[llama.cpp HTTP Server](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。

### 6.4 Exa 交互

Exa 不使用模型供应商的 tool/function calling 参数。普通 Panel 中的指令要求模型返回如下 JSON：

```json
{
  "tool": "exa.search",
  "arguments": {
    "query": "检索内容",
    "num_results": 8
  }
}
```

只有当整个结果能解析为单个 JSON 对象、工具名严格等于 `exa.search`、参数类型和范围全部通过本地校验时，才显示“执行 Exa”按钮。请求必须由用户点击触发，绝不自动执行。Exa 结果成为一个子 Panel，可发送给任意快捷 LLM 路径分析。无效 JSON 或夹杂普通文本的结果始终作为普通 Panel 展示。

## 7. 知识库

知识库定位为备忘录，不做自动 RAG。条目包含文件夹、标题、纯文本正文、标签和可选资产引用。只有用户主动选择的条目才加入请求。首版不实现 embedding、向量搜索、自动切片、后台索引或隐式召回。

## 8. 共享资产库

资产库接收图片、视频和普通附件。元数据包含稳定资产 ID、媒体类型、显示名、内容哈希、大小、可获得的尺寸或时长、来源模块和任务、创建时间、备注以及其他记录的引用。

导入文件会复制到受控内容目录。SHA-256 用于物理去重，但不同来源记录仍然保留。其他模块只保存资产 ID，不依赖临时输出路径。

资产有两种精选状态：

- `active`：精选资产，会出现在所有模块的资产选择器中。
- `archive`：保留资产，只在 Gallery 和原始批次结果中展示。

新生成结果默认进入 `archive`，同时立即出现在当前批次结果区。点击“精选”后进入 `active`。Gallery 展示全部资产，并支持预览、搜索、批量调整状态、导出和删除。仍被其他记录引用的资产默认禁止物理删除，但可以归档。

## 9. 生图工作区

生图是独立领域和独立界面，不与视频共享参数对象或请求表单。

一个图像批次包含 Provider、基础图像参数、有序提示词列表和单项参数覆盖。默认串行执行，也可显式设置并发数。每项可以独立取消、显示失败原因和重试。成功结果导入共享资产库。

内置 stable-diffusion.cpp 适配器默认使用官方原生异步接口：

- `GET /sdcpp/v1/capabilities`
- `POST /sdcpp/v1/img_gen`
- `GET /sdcpp/v1/jobs/{id}`
- `POST /sdcpp/v1/jobs/{id}/cancel`

常用表单展示 prompt、negative prompt、尺寸、seed、采样参数、输入图、mask 和批次数等字段。其他原生字段放在折叠的 JSON 覆盖区，使 stable-diffusion.cpp 新增字段时不必立刻升级工作台。可以提供 `/sdapi/v1/txt2img` 和 `/sdapi/v1/img2img` 兼容预设，但原生异步 API 是默认路径。

官方参考：[stable-diffusion.cpp Server APIs](https://github.com/leejet/stable-diffusion.cpp/blob/master/examples/server/api.md)。

## 10. 视频工作区

视频是独立领域和独立界面，拥有自己的批次模型、预设、校验和结果历史。主要参数包括 prompt、negative prompt、尺寸、seed、时长或帧数、FPS、首帧、尾帧、参考素材和视频专用采样参数。完整能力边界见[视频工作区设计](2026-08-31-video-workspace-design.md)。

### 10.1 HTTP 路径

内置 stable-diffusion.cpp 适配器使用 `POST /sdcpp/v1/vid_gen`，并复用官方原生任务查询和取消端点。用户填写时长时，工作台按 FPS 转换并校验帧数；请求快照同时保留时长、FPS 和最终帧数。

常用表单遵循官方原生视频字段；额外或新增字段放在折叠的 JSON 覆盖区，不与图像参数类型合并。

### 10.2 CLI 路径

视频 CLI 配置是用户编写的原始 Shell 命令模板。工作台提供 prompt、seed、帧数、FPS、首帧、尾帧、参考视频、输出目录和任务 ID 等稳定变量，同时提供 JSON 编码和 Shell 引用形式。实际程序、模型和参数（包括 `ref_video` 等模型专用选项）完全由配置决定。首版 CLI 只在工作台所在主机运行；最小远端 Worker 不传输输入或结果。

CLI 在独立进程组运行，与其他任务共用取消原语。任务界面显示其输出；只在该任务分配的输出目录中发现结果文件。

### 10.3 固定工作区与尾帧

固定视频工作区为 `<data-dir>/video-workspace`。每项任务获得稳定子目录，只暂存用户明确选择的 active 资产。优先链接到资产库受控文件；无法链接时才复制。清单文件记录资产 ID、暂存路径和用途。

尾帧提取使用外部命令配置，文档默认建议 `ffmpeg`。工作台分配输入输出路径、执行命令、验证确实生成一张图片，再将其作为 archive 图片资产导入。用户可立即将其精选为 active，并用作下一条视频的首帧。

CLI 示例和具体模型启动参数始终是用户配置，工作台不硬编码 stable-diffusion.cpp 的模型命令行。

官方参考：[stable-diffusion.cpp 项目文档](https://github.com/leejet/stable-diffusion.cpp)和[原生 Server API](https://github.com/leejet/stable-diffusion.cpp/blob/master/examples/server/api.md)。

## 11. 浏览器界面

顶部一级导航为：

```text
LLM 工作区 | 生图 | 视频 | 后端管理 | Gallery | 知识库 | 配置
```

桌面端统一使用紧凑左栏和大面积右侧工作区。左栏放文件夹、会话或批次、搜索和新建操作。窄屏时左栏收进抽屉，主区变成单列，顶部导航允许横向滚动。

界面遵循渐进展开：

- 默认只展示内容、状态和高频文字操作。
- 完整请求、请求头、Provider 参数、运行元数据、修订记录和高级生成字段全部折叠。
- tooltip 只解释紧凑控件，不承载必要说明或唯一错误信息。
- 优先使用文字按钮，不建立独立图标体系。
- 错误显示在对应 Panel 或任务旁，技术细节折叠。
- 拖拽不是排序或选择资产的唯一方式。
- Gallery 使用响应式媒体网格，窄屏预览可全屏展示。

前端使用语义化 HTML、CSS Grid/Flexbox、CSS 自定义属性和浏览器原生 ES Modules。浏览器调用带版本的 `/api/v1/` JSON 接口，通过 SSE 接收日志和模型增量输出。

## 12. 错误处理与恢复

- API 错误使用稳定 JSON Envelope，包含机器码、面向用户的说明和可折叠技术详情。
- 外部 HTTP 请求具有可配置的连接与总超时，并可由来源任务取消。
- Provider 错误在运行快照中保留状态码和有限长度的响应内容。
- 未完成媒体下载只存在于 `tmp`，不会登记为资产。
- 生成结果逐文件导入，因此部分成功的批次仍能保留有效输出。
- 重启后将未完成的 HTTP/CLI 任务标记为“已中断”，不猜测外部计算是否仍在继续。
- 正常关闭时停止接收新请求、取消自身任务，并终止所有受管后端进程组。

## 13. 验证策略

所有自动化测试只使用 Go 标准库：

- `testing`：迁移、请求组装、模板替换、分支规则、状态机、Exa JSON 校验和资产引用规则。
- `httptest`：JSON API、上传下载、SSE 重连、模拟 llama.cpp 流、模拟 stable-diffusion.cpp 任务和 Exa 错误。
- 临时目录：原子替换、备份恢复、内容去重、工作区暂存和中断任务恢复。
- 短生命周期 Linux Shell Fixture：进程组、原始输出、手动保存、正常停止、强制停止和 crash log。
- 浏览器验收清单：桌面与窄屏、键盘操作、折叠、分支选择、批量执行和资产精选；不为此引入 JavaScript 测试工具链。

## 14. 交付路线

每一期都交付可独立运行和评审的软件：

1. **基础骨架：** Go Module、程序生命周期、数据目录、原子 JSON Store、嵌入式响应式页面、配置和 API 约定。
2. **后端管理：** 运行时配置 CRUD、Shell 进程组、启停控制、就绪检测、SSE 原始输出、手动保存和 crash log。
3. **共享内容：** 资产导入、Gallery、active/archive、引用保护和知识备忘录。
4. **LLM 工作区：** 文件夹、会话、Panel 分支、完整请求快照、llama.cpp 与原始 HTTP Provider、快捷路径、流式结果以及 Exa 检测与执行。
5. **生图工作区：** 图像专用批次、stable-diffusion.cpp 异步 HTTP 适配器、重试、预览和资产导入。
6. **远端进程 Worker：** 独立回环服务、单进程组控制、远端实时日志，以及后端 Profile 本机/Worker 执行选择。
7. **视频工作区：** 视频专用批次、原生 HTTP 和本机可配置 CLI、工作区暂存、时长/帧数换算、尾帧提取和资产导入。

具体 Provider Schema 始终允许在配置中覆盖，内置默认值跟随 llama.cpp 与 stable-diffusion.cpp 官方 HTTP 协议。Server 启动命令和模型专用 CLI 参数不进入工作台硬编码逻辑。

当前进度：基础骨架、后端管理、共享内容、LLM 完整请求工作区、生图工作区和远端进程 Worker 均已交付；视频工作区设计已批准，尚未实施。

## 15. 明确不做的内容

- 原生桌面窗口或 WebView 打包。
- Windows 或 macOS Server 进程管理。
- 鉴权、远程用户隔离或直接暴露公网。
- 远端 Worker 的文件传输、生成代理或多节点调度。
- 自动 GPU/显存调度，以及不同配置间的端口冲突检测。
- 聊天角色语义或自动生成对话历史。
- 自动执行工具请求。
- 向量数据库、embedding、自动 RAG 或后台知识摄取。
- 统一的图像/视频生成参数模型。
- 捆绑模型、AI Server、`ffmpeg` 或生成 CLI。
- 插件执行、任意浏览器脚本或第三方前端包。

## 16. 总体验收标准

一个不依赖第三方 Go/前端包的工作台二进制可以复制到 Linux 主机，指向可写数据目录后直接启动，并通过本机或 SSH 隧道浏览器访问。可选的标准库 Worker 可以单独复制到云端，仅通过 SSH 隧道控制模型 Server 进程。用户无需修改应用代码，即可管理自定义 AI Server、观察原始实时日志、构建有分支的完整 LLM 请求、维护共享资产和知识备忘录，并分别运行图像与视频批量工作流；常规的启动命令、CLI 参数和 HTTP 请求参数调整都通过运行时配置完成。
